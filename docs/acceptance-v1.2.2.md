## 1. 身份机制与真实秘密

| 字段/位置 | 当前含义 | 处理原则 |
| --- | --- | --- |
| roomCode | 可分享的房间标识 | 可以出现在邀请链接及应用日志中 |
| participantId | 随机UUID，同时承担身份定位和Bearer认证；不是公开用户编号 | 视为认证秘密，不展示给另一人、不写应用日志 |
| participantToken | 当前没有独立的该字段或凭证机制 | 不应把不存在的token当作现有保护 |
| `/api/rooms/{roomCode}/participants/{participantId}` | 读取本人草稿的接口，路径内含认证秘密 | 服务端日志将凭证段替换为`[REDACTED]` |
| 邀请链接 | `/room/{roomCode}` | 不含参与凭证、查询参数或片段；加入时签发不同的新参与者身份 |

权限边界必须准确表述：只拥有A自己的凭证和公开房间码，不能读取B草稿。但若取得B的participantId，就已经取得B的Bearer秘密；当前机制不能识别这是凭证窃取，不能宣称即使B凭证泄漏也能阻止冒用。

本次没有迁移身份机制、没有轮换凭证，保留现有房间和客户端兼容性。如果要撤销历史凭证或彻底移除URL内的秘密，需要另行设计凭证轮换/认证迁移，先说明旧房间恢复与客户端兼容影响，不能悄悄强制失效。

## 2. 实际风险与已修复项

### 参与者凭证和私人输入进入日志

此前请求路径直接包含participantId；数据库异常可能带查询参数，解析器错误可能带原始正文；框架默认错误处理还可能向标准错误输出原始异常。

当前修复：

- 仅记录已知路由形状，遮盖参与凭证；剥离查询参数、片段，处理编码、非法编码和未知路径。
- 不序列化请求正文、私人响应正文、请求头等私人输入。
- 错误采用字段白名单，排除原始message、stack、cause、SQL参数、解析器body。
- 接管框架错误响应，避免默认处理器向stderr输出私人输入。
- 保留请求ID、HTTP方法、脱敏路由、状态码、耗时等基本排查信息。详细原始堆栈已主动舍弃，不能声称诊断细节与修复前完全相同；后续应增加安全的错误分类，而不是恢复原始错误文本。
- 草稿响应仅投影本人数据，禁止返回伙伴身份或草稿，并使用`Cache-Control: no-store`。

本轮真实开发工作流日志已观察到`/participants/[REDACTED]`，没有再把该段原始凭证打印出来。自动化测试另外捕获真实HTTP中间件日志和stderr，覆盖正常响应、主动错误、畸形JSON及服务失败。

### 到期后私人记录只失去访问权、没有可靠主动删除

原24小时有效期与API到期判断保留。清理由启动任务和周期任务主动触发，不需要有人再次打开那间到期房间。

当前修复：

- 启动时立即清理；API进程运行期间每60秒再清理。
- 只选择`expires_at <= CURRENT_TIMESTAMP`的房间。
- 复用现有外键级联，事务内删除房间、参与者及其偏好/保留草稿。
- 每批最多100间，一次最多10批；积压留待后续轮次。
- 跳过已锁定记录；同一进程不重叠运行。
- 每批设置1秒锁等待上限、5秒语句执行上限，避免无限等待。
- 失败不输出原始数据库异常，记录安全失败信息，下一个60秒周期重试。

## 3. 保留期、访问截止与实际删除

| 项目 | 当前规则 |
| --- | --- |
| 保留多久 | 创建起24小时，不是最近一次填写起24小时；本次未延长有效期 |
| 什么时候不能访问 | `expiresAt <= 当前时间`后，读取、加入、提交、重选、换组均拒绝，不能返回私人草稿或最终推荐 |
| 什么时候实际删除 | 服务启动时及运行中的每60秒周期；无失败、积压、持续锁定时，在后续清理周期删除 |
| 删除范围 | 房间、其参与者、其偏好及重选保留的私人草稿 |
| 失败后如何重试 | 本轮回滚；下一周期重试；服务重新启动也会立即补清理 |
| 重复执行 | 已删除数据不再命中，可安全重复执行 |
| 正常房间 | 不命中过期条件；数据库回归验证其房间、参与者、草稿逐字段不变 |
| 积压或锁冲突 | 分批处理、跳过锁定记录，下轮继续；不能把60秒周期宣传成严格的物理删除上限 |

### Autoscale的实际限制与低成本方案

已通过发布信息确认现有部署类型为Autoscale。Replit文档说明空闲会缩容到零，进程停止时应用定时器也停止。

因此，**当前实现不能保证在完全无人访问、零实例期间按时物理删除**。过期后API仍拒绝私人读取；下一次进程启动会补清理，但物理删除的最长等待时间没有独立调度保障。

不改变现有部署类型的低改动方案：

1. 经用户确认后配置独立的定时HTTP触发器，按小时访问现有`/api/healthz`以唤醒服务，由启动清理处理积压。
2. 定时器不携带参与凭证，不需要开放新的业务或清理接口；触发失败应重试并告警。
3. 对外保留期说明应写成“到期即不可访问，下一次成功清理删除”，不能承诺到期后60秒必删。按小时触发只是建议频率，仍受启动失败、数据库失败和积压影响。
4. 若必须独立于应用进程、严格按计划执行，可评估Scheduled Deployment/独立清理作业；需另外确认运行配置和数据库访问，不能在本次擅自变更现有部署。

上述外部调度**本次没有启用**，也未向任何第三方发送私人数据。定时唤醒会产生请求与运行用量，不承诺免费。

- https://docs.replit.com/features/publishing/deployment-types

### 用户要求的十项覆盖

1. 日志不含认证秘密：URL脱敏、真实HTTP日志与stderr断言通过。
2. 无效凭证不能读草稿：无效/其他房间凭证返回404。
3. A不能用自己的身份读B草稿：ownDraft仅本人；另一人ID、私人昵称和偏好不出现在对方响应。
4. 邀请链接不含秘密：新增浏览器用例通过真实创建、填写、提交、复制、加入验证；B取得新身份而非A身份。
5. 过期不能提交：到期前存入草稿、到期后PUT拒绝，数据未被修改。
6. 过期不能读草稿：清理执行前GET就拒绝；不返回ownDraft或推荐。
7. 清理删除关联记录：真实数据库验证三表级联删除。
8. 重复清理安全：已清空时重复返回0；周期失败后重试、停止也有测试。
9. 正常房间不受影响：有效房间三类记录逐字段比较不变。
10. 原有双人匹配正常：原算法、API、双端重选与刷新测试通过。

这些测试不是完整渗透测试；不能扩展为未测试的安全保证。

## 5. 数据库与现有房间影响

- **没有数据库结构变更、没有迁移、没有新增表或字段**，复用已有expiresAt及级联外键。
- 清理会实际删除到期数据，这是本次要求的行为，不是只打标记；删除后不能通过应用恢复。
- 未到期房间的代码、凭证、偏好、轮次和确认机制保持兼容。没有强制旧房间失效或让用户重新创建。
- 测试在开发环境执行，使用临时测试房间；数据库保留期回归主要使用可回滚事务。没有对生产数据库执行测试或清理操作。
- 启动清理在开发环境已实际运行，因此不能说“数据库内容完全没有任何变化”；准确说法是结构未改、到期数据按规则清理。
