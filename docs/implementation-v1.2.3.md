## 2. 新认证实现

| 问题 | 实现 |
|---|---|
| participantId与秘密是否分离 | Token模式下分离；ID只作公开标识、外键及缓存隔离 |
| Token如何生成 | Node crypto.randomBytes(32)，256位随机，编码为64位十六进制 |
| 数据库如何保存 | token_hash保存SHA-256哈希，唯一索引；无明文Token列 |
| 如何传输 | Authorization: Bearer；GET自己状态使用/rooms/{roomCode}/me |
| 谁决定访问身份 | 后端通过Token哈希和目标房间定位参与者，不信任客户端ID指定身份 |
| 请求体带别人的ID | 返回403，不修改对方偏好或执行冒名重选／换组 |
| 没有Token／无效Token／其他房间Token | 返回401及中文提示，不返回草稿 |
| 旧URL接口 | Token模式返回426，即使带有效Token也不恢复旧接口 |
| URL编码及大小写 | 认证前解码并统一判断，测试覆盖绕过尝试 |
| 邀请 | 仍然只有/room/{roomCode}，B独立签发身份 |
| 创建／加入响应缓存 | no-store；私人状态、错误响应同样设置no-store |
| 是否注册 | 不需要；没有引入账号、登录或房主角色 |

合法的任一参与者仍可发起原有重选及换组，不新增角色限制。公开创建／加入不要求参与者Token，但最终模式要求非秘密协议版本头`X-Duoxing-Auth: token-v1`，防止旧缓存客户端分配自己无法恢复的身份或占用最后一个名额。版本头不能用于读取草稿或执行受保护操作。

## 3. 前端身份与PWA

原participantId存储键保留。Token按“房间＋参与者”保存到localStorage；主参与者和开发模拟参与者不会共用Token。请求时只读取对应身份的Token，Token不进入URL或React Query键。

刷新后的正常身份恢复已通过真实浏览器测试；不会因刷新重复加入或变成第三个参与者。身份失效或版本过旧时显示中文提示，刷新按钮进行整页重新加载，不自动顶替他人身份。

继续使用localStorage存在同源XSS读取Token的风险。采用该方案是为了保持已有匿名持久化方式，避免本次引入Cookie、CSRF及跨环境适配。没有声称已经解决XSS或真实iOS存储隔离。

manifest、SW及PWA安装配置未修改。新客户端没有包含认证秘密的URL；**旧版已加载／缓存页面在drain期间仍可能发出旧URL请求**。最终Token模式从服务端关闭其读取能力。旧版本实际界面能否完整展示服务端426／401文字，仍需切换后针对旧版本验证；不能让服务器替已缓存的旧JS自动更新。

真实iPhone Safari关闭重开、主屏幕PWA冷启动、跨Safari／独立PWA存储容器身份恢复均未实机验收。Chromium 402px只能验证相应尺寸与浏览器流程，不能替代这些项目。

## 4. 旧房间与生产安全边界

本次采用自然过期，不做凭证兑换或批量失效。房间仍为创建起24小时，到期后不能读取、提交、修改、重选、换组或加入。旧接口同样经过有效期验证；测试覆盖有效旧房间在drain期间可用，到期身份被拒绝。

支持legacy、drain和token三个模式，默认legacy。最终生产Token模式启动会查询数据库：仍有任何有效旧认证房间即拒绝启动。不能只依据等待24小时。

新增字段可空，旧记录保留NULL，不回填、不重编号、不删除有效房间。最终切换前暂停创建约24小时，旧房间继续使用；实际生产暂停与最终切换都尚未执行。

本轮末尾生产只读核对：

- 生产表中尚不存在token_hash字段。
- 生产配置未设置本次新增的DUOXING_AUTH_MODE。

这与“只准备开发实现，不执行生产变更”的授权一致。生产当前旧认证风险不会因为开发代码完成而自动消失。
