# 四区餐厅扩充与评价展示实施计划

**目标：** 为南坪、弹子石、茶园、重邮补充有可靠参考人均的校外堂食门店，并展示可追溯的食客反馈和用餐提醒。

**设计：** 继续使用随代码发布的静态餐厅目录；每个饭局保存完整候选快照。新增可选 feedback 数组，分别记录来源名称、链接、核对日期、简短转述、消费提醒及平台评分/评价数量。评分不参与既有公平排序。没有资料的字段继续未知，不将菜系或单道菜的体验推定为全店辣度。

1. 逐店核对分店、地址、人均、公开堂食条件；小红书与点评存在价格差异时，采用核实后的分店页参考值，保留差异说明。只转述短小事实，不复制完整评价或头像。
2. 先增加失败测试：四区均有至少三个50元内的参考人均候选；有限预算不放宽未知价格；评价字段通过四种响应契约并被双方读取；快照不受目录后续修改影响。
3. 扩充 JSON 目录，增加 shared/restaurant-feedback.ts，更新服务端目录类型与既有生成契约快照。没有原始生成器，不引入无关工具链。
4. 推荐卡使用折叠的“食客反馈与用餐提醒”，链接到原始平台，平台评分明确来源/满分/条数，并与匹配参考分区分。保持已有地图App及网页版入口。
5. 本地类型检查、算法/D1测试、构建；四区50元预算双端浏览器流程、评价展示、刷新一致与320px宽度验证。保留并发、到期、Token与旧饭局回归。
6. 验证完成后创建 after 存档，经 Sites 官方源仓库同步和打包发布。保持公开访问，不推原 GitHub，不改 Replit，不迁移历史数据。

核对日期表示资料读取时间，不表示价格更新日期或今日营业承诺。公开反馈仅为可见样本，不宣称读取全部评论；不根据单条投诉下食品安全结论。
