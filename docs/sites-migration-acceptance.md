## 数据与并发

D1 每个饭局为一个完整状态快照。数据行包含创建、过期时间、内部版本和私有状态；读写直接使用主库。修改按内部版本和未到期条件进行单条 SQL 原子更新，冲突重读、重校验，首次尝试后最多重试五次。连续冲突返回 503 和 Retry-After: 1，不覆盖竞争写入。

Token 使用 32 字节安全随机数，库内仅存 SHA-256 哈希。每次重试重新验证身份、房间寿命和偏好轮次；响应由原 Zod 契约投影，只包含本人草稿。公开写接口仍要求原有升级头及参与者 Token。数据库查询全部参数化，错误日志不记录请求体、Token、参与者身份或 SQL 参数。

房间到期立即拒绝访问，加入、提交、读取、重选和换组均不续期。每次 API 完成后通过 Worker waitUntil 清理最多 100 个过期快照；无人访问时不保证立即物理删除。没有创建收费调度或额外账号服务。
