「都行」v1.2.3 生产升级：

我已阅读阶段B检查报告。

确认Replit的生产数据库迁移
需要通过Publish执行，
无法按照原方案独立应用SQL。

因此，我同意调整执行流程：

将阶段B（加法数据库迁移）
与阶段C（发布drain模式）
合并为一次受控生产发布。

本次授权仅限第一次drain发布，
不授权最终token切换。

========================
一、允许的数据库变更
========================

本次最多允许以下三项：

1.
duoxing_rooms增加：

recommendation_page
integer DEFAULT 0 NOT NULL

2.
duoxing_participants增加：

token_hash text NULL

3.
创建：

duoxing_participants_token_hash_unique

唯一索引。

其中recommendation_page是
本次额外批准的加法变更。

执行前必须确认：

- 当前v1.2.3代码确实需要该字段。
- 默认值0符合原有推荐分页逻辑。
- 不会覆盖现有房间的有效业务数据。
- 不存在其他未列出的数据库差异。

如果有第四项数据库结构变更，
立即暂停并报告。

严禁：

DROP、TRUNCATE、push-force、
删除记录、覆盖生产数据库。

========================
二、首次发布模式
========================

本次Publish必须明确使用：

DUOXING_AUTH_MODE=drain

不能使用：

legacy
token

作为首次发布的实际运行模式。

注意：

旧版本可能忽略新增环境变量。

因此必须区分：

1. 已设置drain配置。
2. 新版本实际运行drain。
3. 旧版本实例已经退出。

不能将三者视为同一件事。

========================
三、发布前检查
========================

请先完成最小范围核对：

1. 确认目标是当前项目生产环境。

2. 确认生产数据库PITR仍然开启。

   用户已在Replit控制台确认：
   PITR On，恢复窗口7天。

3. 确认最终数据库差异
   只有上述三项。

4. 确认本次发布代码
   为已测试的v1.2.3认证实现。

5. 检查当前工作区是否混入
   未获批准的其他产品功能修改。

6. 确认生产构建能够通过。

7. 检查数据库迁移锁等待风险。

   如果发布流程支持设置合理的
   lock_timeout，请采用安全设置。

   如果不支持，请如实说明，
   不要声称已有超时保护。

8. 确认drain模式下：
   - 新建房间返回503
   - 有效旧房间仍能使用
   - 旧房间不会自动延长有效期

如果发现额外数据库变更、
未经测试的代码差异、
无法确认的生产目标
或可能导致数据丢失的问题，

立即停止，不执行Publish。

========================
四、执行首次Publish
========================

只有以上检查全部通过，
且实际发布范围符合本次授权时，
才执行第一次生产Publish。

目标：

- 应用上述三项数据库变更
- 发布v1.2.3兼容代码
- 生产模式为drain
- 暂停新房间创建

不允许自动执行任何后续阶段。

========================
五、发布后验收
========================

请验证：

1. 生产数据库三个变更正确。
2. 房间、参与者、偏好记录未丢失。
3. 线上首页可以访问。
4. API健康检查正常。
5. 生产实际处于drain模式。
6. 创建房间返回预期503。
7. 已有有效旧房间仍能访问。
8. 没有旧版本继续创建旧房间。
9. 原有匹配功能未被破坏。

对于旧实例退出：

优先使用部署状态和实例证据确认。

如果平台无法提供充分证据，
如实标记为尚未确认。

不能仅凭一次创建请求返回503，
就断言所有旧实例已退出。

========================
六、重新统计旧房间
========================

发布完成后，
执行生产只读检查：

active_legacy_rooms

注意：

数据库总房间记录数
不等于有效旧认证房间数。

必须查询当前仍然有效的旧房间。

如果结果为0：

报告已满足该项切换条件，
不需要额外修改旧房间。

如果结果大于0：

只报告数量和失效方案。

我已同意旧测试房间可以作废，
但具体生产数据修改
仍然需要单独批准。

不要自动作废。

========================
七、严格停止条件
========================

第一次Publish及验收完成后，
立即停止。

暂不允许：

- 切换DUOXING_AUTH_MODE=token
- 作废或删除旧房间
- 删除其他生产数据
- 撤销凭证
- 清理历史日志
- 修改匹配算法
- 开发v1.2.4
- 开发v1.3

最终token发布必须再次获得我的批准。
